# SLO / SLI 基线（企业级）

## 目标

定义可观测、可告警、可复盘的服务可靠性目标，支撑企业级运维治理。

## 服务范围

- Web API（认证、权限、用户、模块契约、审计导出）
- 管理台前端（登录、核心路由、模块加载）

## 核心 SLI

- **可用性**：`/api/health/ready` 成功率
- **错误率**：`5xx` 比例（按 API 请求总量）
- **延迟**：关键接口 `p95` 延迟
- **导出链路时延**：审计导出任务从创建到完成的耗时分位数

## 建议 SLO（初始）

- API 月可用性：`>= 99.9%`
- API `5xx` 比例：`<= 0.5%`
- 关键接口 `p95`：`<= 500ms`
- 审计导出完成时延 `p95`：`<= 120s`

## 告警分级（对齐运维手册）

- `P1`：可用性严重下降、认证不可用、数据损坏风险
- `P2`：核心功能不可用或明显退化
- `P3`：非关键功能退化或短时波动

## 发布门禁联动

- 发布后必须校验：
  - `/api/health/ready`
  - `/metrics`
  - `/api/modules/contracts/report?protocolVersion=1.0.0&failOnBreaking=true`
- 若连续 2 个采样窗口未满足 SLO，自动进入回滚评估。

## 数据保留与复盘

- 指标与日志至少保留 30 天。
- 每次 P1/P2 事故需产出复盘（根因、影响范围、修复项、预防项）。
